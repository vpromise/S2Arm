# S2Arm 故障排除（按提示文字查）

**用法**：把屏幕上看到的提示里的几个字（比如「解不开」「没找到完整的 Xcode」「7 天」）拿来，在这一页搜索（Mac：`⌘F`；GitHub 网页：浏览器的页内查找）。每条都按「看到什么 → 是什么意思 → 怎么办」写。

- 第一次用，请先看[使用教程](内测教程.md)。
- 不是报错、只是想问「能不能 / 为什么」，请看[常见问题](常见问题.md)。
- 这里查不到，请按[怎么回报问题](#怎么回报问题)提交。

S2Arm 的出错提示下方通常有一行「**错误代码：**」，比如 `content_unreadable`。每条标题后面的灰字就是这个代码，按代码搜也能找到。

> 📷 截图待补：Mac 上一条出错提示的样子，标出「错误代码」「复制错误摘要」「查看失败任务」三处（建议文件名 `images/故障排除/01-出错提示.jpg`）。

## 一、打开 S2Arm、检查环境时

### 「未打开 "S2Arm"」/「已阻止 "S2Arm" 以保护 Mac」

0.1.0 beta.4 起的 S2Arm 经过苹果公证，不会再弹这个框，**换成最新版**最省事。beta.3 及更早的包没有公证，第一次打开会被系统拦下来，这不是坏了：

1. 弹框里点 **「完成」**。**不要**点「移到废纸篓」：它是默认按钮，按回车会选中它。
2. 打开「系统设置 → 隐私与安全性」，往下翻到「安全性」，点「已阻止 "S2Arm"」旁边的 **「仍要打开」**。
3. 再弹框时点 **「仍要打开」**，输入开机密码或按指纹。

「按住 Control 再点打开」这个老办法在 macOS 26 上已经不管用了，请走上面的步骤。

### 打不开，或者提示要更新系统 `os_unsupported`

Mac 上的 S2Arm 需要 **macOS 26 或更新**，以及 **Apple 芯片（M1 起）**。系统太旧时应用本身打不开，请先升级 macOS。

- 只想给 iPhone 出包、手上是 Intel Mac 或旧系统：可以改用命令行出包，见[使用教程第一节](内测教程.md#一你需要准备的东西)。这条路需要一些电脑操作经验。

### 「当前路径需要 Apple Silicon Mac」 `architecture_unsupported`

这台 Mac 是 Intel 芯片。在 Mac 上玩游戏必须用 Apple 芯片，换一台 Mac 才能解决，重试没有用。

### 「没找到完整的 Xcode」/「需要完整 Xcode……不能仅使用 Command Line Tools」 `xcode_unavailable`

打包要用苹果的免费开发工具 Xcode。

1. 点检查项旁边的「去 App Store 安装」，装完整的 Xcode。只装「命令行工具」不够。
2. 装好后**打开一次 Xcode**，同意许可协议，等它装完初始组件。
3. 回到 S2Arm 点「重新检查」。

### 「Xcode 首次启动任务未完成」/「Xcode 初始设置检查超时」 `xcode_setup_required`

Xcode 装了，但还没完成第一次设置。打开 Xcode，按它的提示点同意、等组件装完，再回 S2Arm 点「重新检查」。

### 「Xcode 的 iOS 平台组件还没装」 `ios_platform_missing`

新装或刚升级的 Xcode（26 起）不自带 iOS 平台，要另下；没下时打 iPhone 包、装到 iPhone 都会失败（Xcode 原话：「iOS 26.5 is not installed. Please download and install the platform」）。只在 Mac 上玩不受影响。

- 在 S2Arm「设置 → 运行与构建环境」里「iOS 平台组件」那一项点「一键下载」，下完自动重新检查；
- 苹果只发这一种包（iOS 模拟器运行时，苹果用它代表「iOS 平台」）：Apple 芯片版约 8 GB（iOS 26.5 为 8.5 GB、iOS 27.1 为 7.9 GB），没有只含真机部分的更小下载；
- 也可以打开 Xcode → 设置 → Components，装上与 Xcode 配套的 iOS 平台；命令行：`xcodebuild -downloadPlatform iOS -architectureVariant arm64`。

### 「缺 Xcode 的 Metal 编译组件」/「Metal 工具链不可用」 `metal_unavailable`

点检查项旁边的 **「一键下载」**（约 1 GB），下完会自动重新检查。

### 「内置 Python 缺失……」/「应用缺少 NSP 读取组件」/「S2Arm 目录不完整」/「着色器转换组件缺失」/「应用自带的共享字体缺失」 `dotnet_unavailable` `reader_unavailable` `engine_incomplete` `tool_missing`

S2Arm 自带的组件缺了或坏了，常见原因是下载不完整，或者从压缩包里只拖出了一部分。

1. 删掉「应用程序」里的 S2Arm。你的游戏库、密钥和存档不在应用里面，不会被删。
2. 重新下载 `S2Arm.zip`，完整解压后再拖进「应用程序」。
3. 打开后点「重新检查」。

## 二、放密钥、放游戏时

### 「无法解密或验证游戏内容」 `content_unreadable`

请核对文件是否完整，以及原始安装包是否包含所需票据。

### 「缺少票据」 `ticket_missing`

请核对源文件是否包含该内容所需的票据。

### 「游戏文件不完整」 `content_truncated`

读取器确认部分内容超出文件末尾。请从原始位置重新复制完整的文件，再重新导入。

### 「密钥版本不足」 `keys_outdated`

请用系统版本更新的 Switch 重新导出 prod.keys，到 S2Arm「设置 → 玩家密钥」重新导入，再导入游戏。

### 「缺少有效的 header_key，无法读取 NSP」/ 放了 prod.keys 但卡片不打勾 `keys_invalid` `keys_missing`

密钥文件不完整，或者放进来的不是 prod.keys。

- 请选择从 Switch 导出的**完整** `prod.keys` 文本文件，不要手工改写里面的内容。
- 原来已经导入的密钥不会被覆盖。

### 「缺游戏本体」/「缺少本体 v0」/「仅更新或 DLC 不能单独打包」 `input_base_missing`

只放了更新包或 DLC。请把游戏**本体**的 NSP / XCI 也放进来，本体、更新、DLC 可以放在同一个文件夹里一起拖。

### 「缺少更新 ……」

本体或 DLC 需要某个更新版本，但你没放。把提示里写的那个更新包也放进来，再放一次。

### 「这款游戏是 32 位程序」/「这款游戏的 32 位 ARM 程序暂不支持」 `guest_isa_unsupported`

S2Arm 目前只支持 64 位的游戏。少数老游戏是 32 位的，暂时打不了包，重试没有用。

### 「读不了「……」：S2Arm 没有读取这个文件夹的权限」 `permission_denied`

游戏放在「下载」「桌面」「文稿」或外接硬盘里，macOS 要你同意才让 S2Arm 读。

1. 打开「系统设置 → 隐私与安全性 → 文件与文件夹」（外接硬盘看「可移除的宗卷」）。
2. 找到 S2Arm，打开对应的开关。
3. 回到 S2Arm 再放一次。

> 📷 截图待补：「文件与文件夹」里 S2Arm 那一行和开关的位置（建议文件名 `images/故障排除/02-文件与文件夹.jpg`）。

### 「所选位置没有 NSP 文件」/「选择 NSP、XCI 文件或包含它们的文件夹」 `input_empty` `input_type_unsupported`

拖进来的文件夹里没有 `.nsp` / `.xci` 文件，或者拖错了文件类型。请确认文件后缀，再拖一次。

### 「Apple ID 已经登录，但这台 Mac 还没有签名团队」 `xcode_team_pending`

第一次用这个账号时，Xcode 还没生成证书和描述文件，光登录账号不够。在「装到 iPhone」页点「解决办法」，打开现成的引导项目：在 Xcode 里选 Personal Team，连上手机点运行一次，回来会自动打勾。

如果 Xcode 已经能用但 S2Arm 查不到团队，可以在同一个地方手动填 Team ID。也可以用「显示 IPA」找到安装包，用 Sideloadly 或 AltStore 自己装，再用访达把资源包拷进 App。

### 「游戏库可用空间不足，复制尚未开始」/「游戏库所在的磁盘空间不够」 `disk_full`

提示里写了需要多少、还剩多少。清出空间后再放一次。原来的游戏文件没有被改动。

- **不要**为了腾空间删掉存档或已经打好的游戏。

### 「复制后校验失败，原始文件未改动」 `content_invalid`

复制过程中数据出错了，常见于外接硬盘接触不良。重新插好硬盘，再放一次；还不行就把游戏先复制到 Mac 自带硬盘上再放。

### 「重新连接存储磁盘，确认文件仍在原位置」 `input_missing`

游戏库所在的外接硬盘被拔掉了，或者原始文件被移动、删除了。插回硬盘，或者从原始文件重新放一次。

## 三、打包时

### 打包很久，进度条好像不动

**第一次打包一款游戏本来就很久**，大部分时间花在提前编好游戏的画面程序（着色器）上，大型游戏在 MacBook Air 上可能超过一个小时。这样做是为了玩的时候不卡。

- 请插上电源，别让 Mac 睡眠。
- 进度条下方会写当前在第几步、已经用了多久。只要「已用时间」还在走，就是在正常干活。
- 之后再打包同一款游戏会快很多。

### 「磁盘空间不足，任务已停止」 `disk_full`

清出空间后重试。**不要**删除存档或上次打包成功的版本。

### 「构建进程被终止，可能内存不足」

Mac 内存不够，系统把打包进程关掉了。请关掉占内存多的应用（浏览器、其它游戏、虚拟机），再点重试。

### 「Metal 着色器编译失败」/「着色器转换失败」/「没有生成可用的着色器，构建已停止」/「部分着色器构建失败：成功 X/Y」

先点「重新检查」确认 Xcode 和 Metal 组件都在。环境没问题还失败的话，通常是这款游戏或这个版本的兼容问题，不是你操作错了：请按[怎么回报问题](#怎么回报问题)把诊断交给我们。

### 「组件 …… 运行失败」/「本地任务失败，请检查日志和输入」/「操作失败，请查看任务日志」 `tool_exit` `job_failed`

这类提示没有具体原因。

1. 点「查看失败任务」，看失败在哪一步。
2. 先重试一次。
3. 还失败就点「复制错误摘要」，按[怎么回报问题](#怎么回报问题)提交。

### 「重新打包这款游戏以恢复完整运行文件」 `runtime_invalid`

打好的游戏文件不完整（比如打包中途断电）。在游戏库里对这款游戏重新打包即可，存档会保留。

## 四、打 iPhone 包时

### 「用数据线连上 iPhone / iPad，或……选机型和系统版本」 `target_required`

S2Arm 要知道你的 iPhone 是哪个型号、哪个系统，才能为它提前编好画面程序。下面两种方法选一种：

- 用数据线连上手机，解锁并点「信任」，S2Arm 会自动认出它；
- 或者点「选机型」，手动选型号和 iOS 版本。

同时连着好几台不同的设备时，先选好要给哪一台出包。

### 「……需要 iOS 18 或更新：请先升级系统」/「这台设备的 GPU 或系统不在当前支持范围内」 `target_unsupported`

需要 **A14 / M1 或更新的芯片**（iPhone 12 起、M1 iPad 起），以及 **iOS / iPadOS 18 或更新**。系统太旧时先升级系统；芯片太旧的设备暂时不支持，重试没有用。

### 「……所用 Xcode 只带 iOS XX 的 SDK……请把 Xcode 更新到最新版」 `xcode_sdk_too_old`

手机的系统比 Mac 上的 Xcode 新。到 App Store 把 Xcode 更新到最新版，打开一次，回来点「重新检查」，再打 iPhone 包。

### 「在「设置」的环境检查中安装 .NET 10 SDK」/「首次准备引擎读取工具需要 Microsoft .NET 10 SDK」 `dotnet_sdk_missing`

第一次打 iPhone 包要一个额外工具（约 2 GB）。按环境检查里的按钮安装，装完点「重新检查」。

### 「应用内置引擎太旧，没有打 iPhone 包的工具」

你用的 S2Arm 版本太旧了，请从发布页面下载最新版。

### 「一键出包结束了，但没找到 IPA」/「生成的 IPA 结构或完整性检查失败」/「iOS 着色器产物缺失或编译平台不匹配」

先重试一次。还失败的话，打开输出文件夹里的 `logs` 文件夹，按[怎么回报问题](#怎么回报问题)提交。

### 「包已出好，只有通用模式」 `direct_unavailable`

**这不是失败**，包可以照常安装和游玩。只是这款游戏暂时只能用「通用模式」：画面兼容性好，但帧率和耗电不如更快的「直连模式」。

如果你愿意帮忙，可以导出诊断反馈给我们。等直连支持这款游戏后，重新打一次包就能用上。

## 五、装到 iPhone 时

### 「没找到已连接的 iPhone / iPad」 `device_not_connected`

1. 用数据线连上手机并**解锁**。
2. 手机上弹「要信任此电脑吗？」时点「信任」。
3. 第一次装还要打开开发者模式：「设置 → 隐私与安全性 → 开发者模式」，打开后按提示重启手机。
4. 回到 S2Arm 再点一次。

> 📷 截图待补：iPhone「开发者模式」开关所在页面（建议文件名 `images/故障排除/03-开发者模式.jpg`）。

### 「打开 Xcode →「设置」→「账户」……登录你的 Apple ID」/ Xcode 里显示「No Accounts」 `xcode_account_missing`

「装到 iPhone」要用你在 Xcode 里登录的 Apple ID 来签名。

1. 打开 Xcode →「设置」→「账户」，点「+」登录 Apple ID（免费的就行）。
2. 回 S2Arm 再点一次「装到 iPhone」。

Xcode 偶尔会自己退出登录，再登一次就好。不想用 Xcode 登录的话，也可以改用 AltStore 安装，见[使用教程第八节](内测教程.md#八装到-iphone)。

### 「解锁这台 iPhone……装机过程中别锁屏」 `device_locked`

手机锁屏了。解锁、停在主屏幕，再点一次「装到 iPhone」，安装过程中别让手机锁屏。

### 「免费 Apple ID 最多同时装 3 个自签 App、每周最多注册 10 个包名」 `free_app_limit`

这是苹果对免费账号的限制，不是 S2Arm 的问题。

- 先在手机上删掉不玩的自签 App，再装；
- 或者过几天，等名额恢复后再试。

### 「签名」那一步失败 / 「Failed Registering Bundle Identifier」 `signing_failed`

苹果拒绝了这次签名，常见原因有：

- 名额用完了，见上一条；
- 这个 App 的标识被别的账号占用了；
- Xcode 账号掉了登录。

请先确认 Xcode「设置 → 账户」里能看到你的 Apple ID，再试一次；还不行就改用 AltStore 安装。

### 「装好的包能用；要在 iPhone Duo 等新机型上铺满全屏……」 `shell_sdk_old`

包是用比 iPhone 系统旧的 Xcode 出的（例如 Xcode 26 出的包装到 iOS 27 的手机）。iOS 按包链接的 SDK 判断 App 认不认识这台机型：不认识的新机型（如 iPhone Duo）会把整个 App 按旧 iPhone 尺寸缩小在屏幕中间、四周留黑。

- 把 Xcode 更新到不低于 iPhone 系统大版本的版本（iOS 27 → Xcode 27）；
- 在启动器里选这个 Xcode，重新打 iPhone 包再装。

### 「资源包已传完，还差最后一步……」 `manual_unpack_required`

资源包已经完整传到手机，只是电脑这边打不开手机上的 App，不用重新安装或重推。

- 在 iPhone 上打开 S2Arm，选这款游戏；
- 保持 App 在前台、别锁屏，等它导入完就能玩。

### 「换一根支持 USB 3 的 USB-C 数据线……」 `usb_slow`

数据线或接口太慢，大型游戏的资源包要拷很久。

- 换一根支持 USB 3 的 USB-C 线，直接插在 Mac 自带的口上，不要经过扩展坞或显示器上的口；
- 只有 iPhone 15 Pro 及更新的 Pro 机型支持 USB 3，其它机型本来就只有 USB 2 的速度。

### 用 SideStore 装的游戏打不开，或者大游戏一进就退 `iml_missing`

**SideStore 0.7.0 重新签名时，会丢掉 S2Arm 需要的「提高内存上限」权限**，大型游戏会因为内存不够打不开。请改用下面任意一种方式重新安装：

- Xcode（「装到 iPhone」）；
- AltStore Classic v2.3；
- 已经装好的，可以用 GetMoreRam 给这个 App 补上权限后重装。

游戏里如果看到「这台机上装的包签名丢了「提高内存上限」权限」，也是同一个原因。

## 六、在 iPhone / iPad 上打开游戏时

### 一打开就提示要拷「……资源包」/「在 Mac 的 S2Arm「打包任务」里，点这款游戏的「在访达中查看产物」」

App 里只有程序，游戏数据要单独拷进去。

1. 用数据线连上 Mac，打开「访达」，在左边选你的 iPhone。
2. 切到「文件」标签，把「<游戏>资源包」文件夹**整个**拖到这款游戏的 App 上。
3. 等进度走完（大游戏要几分钟）。

也可以直接在 S2Arm 里点「装到 iPhone」，它会自动拷。详见[使用教程第九节](内测教程.md#九把游戏资源拷进-iphone)。

### 多款游戏的 S2Arm App：游戏卡片显示「需要游戏数据」，点了提示「还缺游戏资源」/「游戏资源不完整」

一个 App 装了多款游戏时，每款游戏的资源单独放在本 App「文件」里的 `games/<游戏编号>` 文件夹里。卡片显示「需要游戏数据」就是这款的资源还不在手机上（或只拷了一部分），这时不能开始游戏。

- 在 Mac 上的 S2Arm 里对这款游戏点「装到 iPhone」，资源会自动拷进对应的文件夹；
- 或者用访达把它的「……资源包」文件夹拷进 `games/<游戏编号>`。

拷好后回到 App，卡片会自动变回可以开始（也可以在提示里点「重新检查」）。

### 「游戏没能启动」+「游戏文件缺失，请重新导入」 `game_files_missing`

游戏开始运行时找不到它的程序文件（资源包里的 `exefs/main.npdm`）：资源没拷进来，或拷到一半断了。在 Mac 上的 S2Arm 里对这款游戏再点一次「装到 iPhone」，然后从后台划掉 App 再打开。

### 「游戏资源还没传完」/「游戏资源传到一半停住了」

资源还在从 Mac 拷进手机时就打开了 App。不用做任何操作：传完会自动开始导入。显示「停住了」说明 Mac 那边的传输断了（线松了、S2Arm 关了），在 S2Arm 里对这款再点一次「装到 iPhone」，会接着传完，App 这边自动继续。不用删文件夹重拷。

### 「正在导入游戏资源（第 X / Y 批）」一直不动 / 导入到一半没了

导入时 App 必须**保持在前台、不能锁屏**。切走或锁屏会中断导入，重新打开 App 会接着导。

### 「游戏资源导入完成」之后还是进不去

0.1.0 beta.3 起导入完成后会自动进入游戏。如果停在这一步不动，或用的是更早的包：**从后台划掉 App，再重新打开**；还不行就按[怎么回报问题](#怎么回报问题)提交。

### 「打包失败（写 zip 出错，可能是手机空间不够）」

这是导出诊断包时手机空间不够。清理一些照片或 App 后再导出。

### App 打不开 / 一点就闪退（过了几天）

用免费 Apple ID 装的 App **7 天后会过期**，过期后打不开。**存档不会丢**，续签以后就能接着玩，也不用重新拷资源包。

- 用 AltStore 装的：Mac 上开着 AltServer、和手机连同一个 Wi-Fi，AltStore 会自动续签；也可以打开 AltStore 点「刷新全部」。
- 用 S2Arm「装到 iPhone」装的：连上手机再点一次「装到 iPhone」。

### 「上次 S2Arm 好像没有正常退出（卡住、被系统关掉或闪退）」/「把上次的诊断发给我们？」

游戏上次闪退或卡死了，App 想把上次的记录发给你，让你转交给我们。点「发送诊断」，用隔空投送或「存到文件」保存这个 zip，附到问题回报里。诊断包里没有存档、密钥和游戏文件。

### 「游戏画面初始化失败，游戏已暂停」

画面启动失败。

1. 从后台划掉 App，再重新打开。
2. 还不行的话，在游戏里**四指同时长按屏幕 1.5 秒**打开设置，点「导出诊断包」，按[怎么回报问题](#怎么回报问题)提交。

### 游戏很卡，特别是刚进新场景时

- 第一次进新场景时可能会顿一下，同一个场景再进就好了。
- 如果一直卡：确认打 iPhone 包时选的**机型和系统版本**和你手上的设备一致。包是专门为选中的设备准备的，装到别的机型或别的系统大版本上会边玩边准备画面，就会变卡。换设备或升级大版本后，请重新打一次 iPhone 包。

### 「选定的触屏布局未能加载，已临时使用默认布局」

你选的触屏按键布局文件坏了或被删了。四指长按打开设置，在「触屏布局」里重新选一个，或者恢复默认布局。

### 手柄没反应 / 「不支持震动」

- 先在 iPhone「设置 → 蓝牙」里确认手柄已经连上。
- 有的手柄不支持震动，或者 iPhone 本身没有震动马达（部分 iPad），出现这条提示是正常的。
- Switch 2 Pro 手柄要在这款游戏的「设置」里单独打开适配，见[手柄说明](../runtime/ns2pro/README.md)。

## 七、在 Mac 上启动游戏时

### 「启动需要 Apple Silicon、macOS 26+ 和可用的系统 Metal 图形设备」

到「设置」里点「重新检查」，看哪一项没通过。Mac 上玩需要 Apple 芯片和 macOS 26 或更新；检查都通过还报这条，请按下面的方法回报。

### 「游戏运行遇到引擎兼容问题」

这款游戏在当前版本里还有兼容问题，不是你操作错了。请在菜单栏「S2Arm → 导出诊断包…」导出诊断，按下面的方法回报。

### 「此游戏的输入映射无法读取，请先修复或重新保存键位」

键位设置文件坏了。到「键鼠与手柄映射」里重新设一遍、保存即可。

## 怎么回报问题

1. 先在 [Issue 列表](https://github.com/jhaizhou-ops/S2Arm/issues)里用提示文字搜一下，看有没有人报过。
2. 没有的话，[新建 Issue](https://github.com/jhaizhou-ops/S2Arm/issues/new/choose)，选「问题回报」模板，填写这些信息：
   - 游戏名和版本；
   - 设备和系统；
   - 安装方式（Xcode / AltStore）；
   - **包号**；
   - 看到的提示原文或错误代码；
   - 能不能重复出现。
3. 附上诊断包，导出方法见[使用教程「遇到问题怎么回报」](内测教程.md#遇到问题怎么回报)：
   - **Mac**：菜单栏「S2Arm → 导出诊断包…」，或在出错提示里点「复制错误摘要」；
   - **iPhone**：游戏中四指长按 1.5 秒 →「导出诊断包」。

**请不要上传 prod.keys、游戏文件、资源包或存档。**
